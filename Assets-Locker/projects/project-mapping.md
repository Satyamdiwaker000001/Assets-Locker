# Project-to-Resource Mapping

Use this as a selection guide, not a rigid prescription.

| Project type | Relevant categories | Selection considerations |
|---|---|---|
| Portfolio | Inspiration, typography, imagery, animation, responsive patterns | Performance, accessibility, personal identity |
| Marketing / landing page | Inspiration, typography, photos, illustrations, backgrounds | Clear hierarchy, responsive behavior, licensing |
| SaaS dashboard | UI components, design systems, forms, charts, UI states, architecture | Data density, reusable patterns, accessibility |
| LMS | Architecture, forms, responsive patterns, testing, accessibility | Roles, course flows, progress states |
| Job portal | UI components, search/filter patterns, forms, UI states, testing | Application flow, validation, responsive layouts |
| Admin panel | Data visualization, tables, UI states, accessibility, performance | Large datasets, empty/error states, keyboard use |
| Enterprise application | Domain architecture, security, testing, performance, CI/CD | Maintainability, permissions, observability |
| Design system | Components, tokens, accessibility, documentation, visual regression | API consistency, governance, adoption |

## Selection record

For each project, capture the resource, the feature where it is used, why it was selected, and any license or maintenance concerns.
