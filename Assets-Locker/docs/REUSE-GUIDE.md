# Reuse Guide

## Selection workflow

1. Define the product requirement before selecting an asset or library.
2. Match the resource to the project's framework, accessibility needs, and maintenance capacity.
3. Treat inspiration as a reference, not a mandate to copy another product's identity.
4. Evaluate responsive behavior, interaction states, keyboard support, and performance.
5. Inspect license and attribution terms before adding third-party assets to a project.
6. Check whether the project already has an equivalent dependency.
7. Understand, adapt, and test snippets instead of blindly copying them.
8. Record why and where a resource was used.

## Project considerations

- **Portfolio / landing page:** visual direction, typography, imagery, responsive patterns, and motion.
- **SaaS dashboard:** design systems, forms, tables, charts, empty/error states, and architecture.
- **LMS / job portal:** navigation, search/filter patterns, forms, role-aware UX, and testing.
- **Admin / enterprise tool:** dense data presentation, accessibility, permissions-aware flows, performance, and maintainability.
- **Design system:** component primitives, tokens, documentation, accessibility, and visual regression.

## Avoiding dependency sprawl

Consider bundle size, active maintenance, accessibility behavior, customization cost, framework fit, and future upgrade effort before adopting a library.

## Usage notes

When a resource is used, update its record with the project name, relevant feature, and a short note about how it was applied. Do not store secrets or private project information in this public repository.
