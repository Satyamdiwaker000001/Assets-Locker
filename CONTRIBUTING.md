# Contributing to Assets Locker

Assets Locker is curated for practical reuse. Keep entries accurate, concise, and easy to evaluate.

## Adding a resource

1. Select the closest primary category under `catalog/`.
2. Search the catalog for an existing equivalent.
3. Add a record using `templates/resource-template.md`.
4. Use the canonical URL where possible.
5. Explain what the resource is useful for and when to use it.
6. Record the applicable stack and project types when known.
7. State license and attribution status honestly.
8. Set status to `to-review` unless an actual review has been completed.

## Quality rules

- Do not invent features, pricing, compatibility, maintenance status, or license permissions.
- Do not copy third-party assets into this repository without permission.
- Avoid referral links and promotional descriptions.
- Prefer official documentation for technical implementation claims.
- Add review dates only when a review actually occurs.
- Archive broken or obsolete entries rather than silently deleting useful history.
- Never add credentials, private URLs, or sensitive project data.

## Naming conventions

- Filenames: lowercase kebab-case.
- Tags: lowercase kebab-case, for example `react`, `dashboard`, `accessibility`.
- Dates: ISO format `YYYY-MM-DD`.
- One primary category per resource; use tags for cross-category discovery.

## Suggested commit messages

- `docs: add design inspiration resources`
- `docs: verify icon library metadata`
- `docs: archive obsolete resource`
- `docs: clarify reuse guidance`
